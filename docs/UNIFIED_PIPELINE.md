# Единый экспериментальный пайплайн

## Назначение и границы

Новый протокол `english_geometry_unified_v1` объединяет чистые специализации и
смеси целей. Исторические конфигурации, метрики и команды `src/experiment.py`
сохранены. После завершения всех 69 запусков статьи и галерея переведены на
новые результаты. Источник публикации закреплён в `configs/publication.json`;
метрики и текст связывает `src/publication/unified_assets.py`.

Полный эксперимент завершён и проверен; см. `reports/english_geometry_unified_v1/full/VALIDATION.md`.
Ни одна команда сборки статьи не запускает обучение или оценку модели.
Описания smoke и оценок времени ниже сохранены как история разработки протокола.
Коммит и push требуют отдельного решения автора.

## Фиксированный дизайн

| Параметр | Значение |
|---|---|
| Модель | sentence-transformers/all-MiniLM-L6-v2 |
| Revision | `1110a243fdf4706b3f48f1d95db1a4f5529b4d41` |
| Длина | 128 токенов |
| Режимы | 21 точка решётки STS:Cls:Ret, центр 1:1:1, контроль SimCSE |
| Повторы обучения | 42, 43, 44 |
| Число обучений | 69, каждое независимо от M0 |
| Бюджет | 270 шагов, batch 64 |
| Оптимизация | AdamW, LR 2e-5, weight decay 0.01, warmup 0.1, clipping 1.0 |
| Потери | SimCSE; CoSENT scale 20; supervised contrastive; retrieval MNRL с hard negative |
| Температура | 0.05 |
| Вычисления | BF16, eager attention, детерминированные алгоритмы |
| Геометрия | Шаги 0, 68, 135, 270 для всех режимов |
| Промежуточное качество | Gate на шагах 68 и 135 для шести заранее заданных режимов |
| Конечное качество | Полный набор для всех режимов |

Доля цели определяет число шагов, а не число токенов. Расписание использует
прежнее распределение целочисленных шагов и детерминированное перемешивание.
В логах сохраняются фактические числа шагов, примеров и токенов для каждой цели.
`forward_tokens` включает оба dropout-представления в контроле и все три текста
поискового триплета; это не число уникальных текстов.

Контрольные режимы траекторий: control, три чистые вершины, 1:1:1 и 20:0:80.
Исходная M0 фиксирована, общая для всех seed обучения. Оценка M0 выполняется один
раз на модель. Репликация её строки для парных дельт не является независимым опытом.

## Данные и оценка

Используются существующие подготовленные файлы `data/processed/`: WikiText,
STSBenchmark, AG News и MS MARCO triplet-hard, а также фиксированные диагностические
выборки. Подготовка новых данных и загрузка новых обучающих источников не входят
в этот запуск. Хеши файлов, существующих JSON-аудитов, конфигурации, кода и uv.lock
сохраняются в `protocol.json`.

Конечная оценка включает прежние 16 MTEB-задач на английском языке, AG News,
MS MARCO gate и дополнительные clean_exact версии пяти STS-задач. Исходные STS
результаты сохраняются, но в семейном агрегате используются очищенные варианты.
Классификационный перенос всегда исключает AG News.

Промежуточный gate: STSBenchmark.clean_exact, BIOSSES, Banking77Classification,
EmotionClassification, TwentyNewsgroupsClustering.v2, RedditClustering.v2, SciFact,
NFCorpus; отдельно AG News. Неочищенный STSBenchmark также остаётся в артефактах.
Его семейные показатели не смешиваются с полными агрегатами. На конечном шаге
gate вычисляется из соответствующего подмножества полной оценки.

Evaluation seed и geometry seed фиксированы на 42 независимо от seed обучения.
Поэтому SD между повторами преимущественно характеризует различия обучения,
а не намеренную смену seed классификатора или диагностических пар.

Данные MTEB фиксируются при первой загрузке отпечатками Dataset; для retrieval
хешируются corpus, queries и qrels. Изменение содержимого между запусками приводит
к отказу, а не к молчаливому объединению. Эти отпечатки контролируют совместимость,
но сами по себе не являются аудитом отсутствия пересечений.

Ограничения прежнего аудита сохраняются: проверка точных нормализованных совпадений
не доказывает отсутствие семантических дублей и не раскрывает предобучение M0.
Предметные геометрические диагностики по STS/AG News/MS MARCO вычисляются на
обучающих текстах и явно помечены `in_sample_training_data`.

## Изменения измерительного протокола

1. Исправлен kNN: `kneighbors(X=None)` уже исключает сам объект. Старый дополнительный
   срез удалял ближайшего соседа. Новый код получает ровно k соседей без self;
   версия — `geometry_v2_knn_self_excluded`. Старые метрики не пересчитываются.
2. Диагностические тексты, пары и evaluation seed одинаковы между ветвями.
   Пары для расстояний не включают сравнение объекта с самим собой.
3. Геометрия и оценка изолированы от RNG обучения; восстанавливаются также режимы
   train/eval всех модулей. Снимки включают полный спектр ковариации.
4. Eager attention и детерминированные вычисления выбраны после проверки, выявившей
   небольшие расхождения повторных GPU-запусков с прежним автоматическим выбором
   реализации attention. Побитовое равенство не обещается между разными GPU,
   версиями библиотек и драйверами.

## Команды

Из корня репозитория:

```bash
uv run python src/unified_experiment.py plan
uv run python src/unified_experiment.py smoke
uv run python scripts/check_unified_smoke.py
uv run python src/unified_experiment.py report --smoke-results
```

Smoke обучает пять режимов по 20 шагов, измеряет уменьшенные геометрические
выборки, две технические метрики и BIOSSES. Это проверка исполнения, а не
укороченный научный эксперимент. Проверочный скрипт дополнительно прерывает
смешанную ветвь на шаге 10, продолжает её и сравнивает хеш конечных весов с
непрерывным запуском. Smoke нельзя экспортировать как полный симплекс.

После отдельного решения о полном запуске:

```bash
uv run python src/unified_experiment.py run
# Та же команда продолжает прерванный запуск.
uv run python src/unified_experiment.py run --models all_minilm --seeds 42 --regimes mix_s020_c000_r080
uv run python src/unified_experiment.py evaluate --models all_minilm --seeds 42 --regimes mix_s020_c000_r080
uv run python src/unified_experiment.py report
uv run python src/build_gallery.py --experiment english_geometry_unified_v1 --model all_minilm
```

`evaluate` оценивает последнюю сохранённую точку, если это шаг измерения.
Для продолжения обучения и завершения всех запланированных измерений используйте
`run`. Состояния всех промежуточных моделей не архивируются: остаются измерения,
последняя точка восстановления и конечная модель.

## Восстановление и хранение

Каждые 25 шагов и перед измерением атомарно сохраняются веса, AdamW, scheduler,
RNG, расписание и позиции потоков батчей. После аварии повторяются только шаги
после последнего сохранения. Журнал приводится к состоянию checkpoint, а не
дополняется дублирующими строками. Нельзя одновременно запускать двух исполнителей
для одной и той же ветви.

Артефакты оценки изолированы по модели, seed, режиму и шагу; сохранённые результаты
проверяются по идентичности checkpoint. Завершённые задачи повторно не вычисляются.
При несовместимости кода или конфигурации нужен новый experiment_id; автоматического
продолжения с новыми настройками нет.

Полные запуски: `runs/english_geometry_unified_v1/full/`.
Smoke: `runs/english_geometry_unified_v1/smoke/<protocol_hash>/`.
Разные версии технической проверки изолированы по хешу; не включать их результаты
в научную статистику. Проверка возобновления хранится в `smoke_verification/`.

Тяжёлые веса, checkpoint, NPY и NPZ игнорируются Git. JSON/CSV метрик и манифесты
видимы Git. По умолчанию конечные веса и последние optimizer checkpoints сохраняются;
автоматического удаления после оценки нет. Для 69 MiniLM-запусков предварительная
оценка составляет около 39,5 ГиБ с резервом 5 ГиБ, без роста внешних кэшей.
Перед запуском выбранного набора проверяется свободное место; затем проверка
повторяется перед сохранениями. Для других моделей оценка 0,5 ГиБ на запуск
не является надёжной: требуется отдельный расчёт хранения.

При нестабильном доступе к Hub можно повторить команду с
`HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1`, но только если нужные модели и наборы
данных уже закэшированы. Проверки отпечатков остаются активными; offline не
разрешает подменять другую версию корпуса. На этой машине финальный smoke был
продолжен таким способом после сетевой задержки.

## Отчёты и галерея

Единый экспорт содержит `runs.csv`, `training.csv`, `scores.csv`, `geometry.csv`
и `spectra.csv`. Таблицы отдельной модели содержат абсолютные результаты,
дельты, остатки смешивания, геометрические и прикладные gate-траектории,
средние и SD. Пропорции режимов хранятся в `bundle.json` отдельными полями.
Дополнительно экспортируются `balance.csv` с худшей семейной дельтой и
`pareto.csv` с фронтами по средним. Принадлежность такому фронту не является
проверкой статистической значимости или причинности.

Проверки полноты требуют все режимы, seed, задачи и контрольные точки. Неполная
таблица получает статус `gallery_ready: false`; усреднение по случайно оставшимся
задачам не допускается. Точки симплекса не заполняются интерполяцией вместо измерений.

Галерея строит пять dense-рисунков прежними функциями. В новом рисунке траекторий
показываются четыре чистых/контрольных режима; полные траектории шести выбранных
режимов доступны в CSV. Ракурсы сохранены. При необходимости диапазоны абсолютной
матрицы расширяются, чтобы не обрезать новые значения. По умолчанию остаётся
историческая галерея. Проверка адаптера:

```bash
uv run python src/build_gallery.py --experiment historical
uv run pytest -q
uv run python scripts/verify_migration.py
```

Новый набор отчётности не доказывает причинное влияние одной геометрической
характеристики: вместе меняются данные, целевые функции и представления.
Равные шаги не означают равные FLOP или равную силу оптимизации разных потерь.

## Проверка реализации 23 сентября 2026 года

Финальная техническая проверка записана в
`reports/english_geometry_unified_v1/smoke/020ecbadb0f8/validation.json`.
Пять режимов завершили по 20 шагов; хеш конечных весов смешанной ветви после
прерывания на шаге 10 совпал с непрерывным запуском. Дополнительно был прерван
процесс во время сетевого обращения при оценке STS-ветви; продолжение в offline
режиме завершило недостающие задачи без повторения уже выполненных обновлений.
82 секунды в validation.json — время последнего продолжения проверочного скрипта,
а не суммарное время с предшествующим ожиданием сети.

Автоматические проверки покрывают точность kNN, изоляцию RNG, восстановление,
идентичность кэшей, неполные семейства, линейные остатки и сборку пяти рисунков
на синтетическом полном наборе. Все пять исторических dense-PNG через адаптер
совпали попиксельно с изображениями compact-статьи. Исходные 2408 исследовательских
файлов прошли проверку контрольных сумм. Новые результаты не добавлены в статьи.

Промежуточные smoke-попытки до окончательной настройки детерминизма также остались
в локальных каталогах. Они технические, имеют другие идентичности протокола и
не входят в финальный отчёт. Исторические checkpoints не удалялись.

## Оценка времени большого запуска

В исторических артефактах 69 смесей медиана времени обучения вместе с прежней
геометрией составляет 41,1 с на ветвь. Сумма `evaluation_time` по полному набору
MTEB имеет медиану 56,2 с, а по восьми задачам gate — 13,7 с. Эти времена не
включают все загрузки, дополнительный аудит/clean STS, AG News и запись файлов.
Прямой перенос этих величин на новый план даёт около двух часов как исходную
арифметическую оценку, но не как обещание длительности.

Для планирования разумен резерв **3–5 часов при прогретых кэшах**, свободном GPU
и исправном доступе к данным: добавлены eager attention, предметная геометрия
на промежуточных шагах и записи optimizer checkpoint. Это предварительная
оценка, не замер полного нового протокола. Сетевые таймауты могут увеличить
время существенно; после первой полной ветви оценку нужно уточнить.

Полный запуск из текущего состояния диска не рекомендуется: после smoke свободно
около 24 ГиБ, тогда как предварительная проверка всего набора требует около
39,5 ГиБ. Команда `run` откажется начинать выбранный набор при недостатке места.
